PR A of a 3-PR stack cut off `ps/all-our-charts-used-paul` (PR #42). This one closes
the React→Angular gap and gives the Angular package a real render-test harness.
PR B adds the specialty gallery charts + multi-series `Sparkline`; PR C adds the
Storybook/Chromatic surface for both.

<Section id="why" title="Why this shape">

The Angular package has 16 components and exactly one test file —
`packages/angular/src/__tests__/chart-geometry.test.ts`, which runs in
`environment: 'node'` because the geometry core is pure TS. Nothing has ever
rendered an Angular template in CI. That was fine while every Angular component
was a thin class over shared CSS, but four of the eight ports here
(`Ticker`, `TiltCard`, `Spotlight`, `Textarea`) carry real behaviour — pointer
math, an rAF scroll loop, a live character count — and shipping those untested
would put the interesting half of the package on trust.

So the infra lands first, in the same PR, and every port arrives with a render
test that pins the same behaviour its React test pins.

</Section>

<Section id="infra" title="Test infrastructure">

Angular 21 is already installed (`@angular/core` 21.2.18, `@angular/common`).
The package builds with plain `tsc`, so components are JIT-compiled at runtime —
which means tests need `@angular/compiler` present and nothing more exotic.
Angular 21 `TestBed` supports zoneless change detection, so `zone.js` stays out.

| File | Change | Detail |
|---|---|---|
| `packages/angular/package.json` | add devDeps + keep `test` script | `@angular/compiler`, `@angular/platform-browser`, `jsdom`. No `zone.js` — `provideZonelessChangeDetection()` instead, which is Angular 21's default direction and avoids a global patch that would leak into the geometry tests. |
| `packages/angular/vitest.config.ts` | two projects, not one env | The geometry test stays on `environment: 'node'`; a second project runs `src/__tests__/**/*.spec.ts` on `jsdom` with the setup file. Keeps the pure-TS suite honest — it must not silently start depending on a DOM. |
| `packages/angular/test-setup.ts` | new | `import '@angular/compiler'` then `TestBed.initTestEnvironment(...)` with the zoneless provider. Mirrors `packages/react/test-setup.ts`. |
| `packages/angular/tsconfig.json` | no change | `src/__tests__` is already excluded from the build. |
| `packages/angular/src/__tests__/render.ts` | new helper | `renderComponent(Cmp, inputs)` → `{ fixture, host }`. Wraps `TestBed.createComponent` + `setInput` + `detectChanges` so 8 spec files don't each repeat it. |

<Section id="ports" title="The 8 ports">

Every port reuses the CSS that already ships in `@paul-portfolio/css` — none of
these adds a stylesheet. The React source is the contract; the Angular twin
matches its DOM, class names, and ARIA exactly.

| React source | New Angular file | Selector | Reuses | Detail |
|---|---|---|---|---|
| `packages/react/src/Textarea.tsx` | `packages/angular/src/textarea.ts` | `paul-textarea` | `textarea.css`, `input.css` (`.input__wrapper`, `.input__helper`) | Hardest of the form ports: the live `showCount` counter is derived state. React tracks controlled vs uncontrolled; Angular takes `value` as an input plus a `valueChanged` output and counts off the DOM event, matching how `PaulInputComponent` already works. `hideLabel` swaps the label class to `sr-only`. |
| `packages/react/src/Select.tsx` | `packages/angular/src/select.ts` | `paul-select` | `select.css` | Options come in as `<ng-content>` so callers pass native `<option>`s — no options-array API that React doesn't have. `orientation="horizontal"` adds `.select__wrapper--horizontal`. |
| `packages/react/src/FilterBar.tsx` | `packages/angular/src/filter-bar.ts` | `paul-filter-bar` | `filter-bar.css` | Thinnest port. Renders a real `<section aria-label>` wrapping `.filter-bar__row` around `<ng-content>`, so the landmark is a genuine `<section>` rather than a class on the host element — matching the React DOM exactly. |
| `packages/react/src/InfoTip.tsx` | `packages/angular/src/info-tip.ts` | `paul-info-tip` | `info-tip.css`, `PaulTooltipComponent` | React composes `Tooltip`; Angular does the same via `imports: [PaulTooltipComponent]`. Note `PaulTooltipComponent` takes `text: string` where React's `Tooltip` takes a `ReactNode` — so the Angular `InfoTip` exposes `content: string`. Disclosed narrowing, not a silent one. |
| `packages/react/src/Ticker.tsx` | `packages/angular/src/ticker.ts` | `paul-ticker` | `ticker.css` | The one with real machinery: two modes (`scroll`/`marquee`), an rAF ambient scroll, hover/touch pause with a 4s touch resume, a duplicated aria-hidden clone whose focusables get `tabIndex = -1`, and a reduced-motion branch that drops the clone and the loop entirely. Needs `afterNextRender` + `DestroyRef` for the rAF lifecycle. |
| `packages/react/src/TiltCard.tsx` | `packages/angular/src/tilt-card.ts` | `paul-tilt-card` | `tilt-card.css` | Pointer-driven 3D tilt writing `--paul-tilt-x/y` and `--paul-glare-x/y` on the inner element. Reduced motion → flat card, no handlers bound. |
| `packages/react/src/GradientBackground.tsx` | `packages/angular/src/gradient-background.ts` | `paul-gradient-background` | `gradient-background.css` | No JS motion at all — sets `--paul-gradient-image` / `--paul-gradient-duration` and a `data-animate` attribute; the CSS handles the reduced-motion gate. Straight port. |
| `packages/react/src/Spotlight.tsx` | `packages/angular/src/spotlight.ts` | `paul-spotlight` | `spotlight.css` | Cursor-tracking radial glow via `--paul-spotlight-x/y`. Reduced motion → glow pinned centre, `data-active` always on. |

Shared support:

| File | Change | Detail |
|---|---|---|
| `packages/angular/src/prefers-reduced-motion.ts` | new | Angular twin of `packages/react/src/usePrefersReducedMotion.ts`. A tiny injectable returning a `Signal<boolean>` backed by `matchMedia`, SSR-safe (false when `window`/`matchMedia` is absent). Consumed by `ticker`, `tilt-card`, `spotlight`. Three components would otherwise each hand-roll the same listener. |
| `packages/angular/src/index.ts` | 8 new exports + the signal | Barrel stays alphabetically grouped the way it is now (form → overlay → decorative → charts). |

</Section>

<Section id="risks" title="Risks">

| Risk | Mitigation |
|---|---|
| esbuild's decorator output may not JIT-compile under Angular 21 | Prototype `render.ts` + one trivial component first; fall back to `@analogjs/vite-plugin-angular` (see `q-decorators`). This is the first thing built, so it fails cheap. |
| Zoneless TestBed changes when `detectChanges` is needed vs `await fixture.whenStable()` | The `renderComponent` helper owns that so it's decided once, not eight times. |
| `Ticker`'s rAF loop leaking across tests | Component tears the loop down through `DestroyRef`; the spec asserts the teardown, and fixtures are destroyed in `afterEach`. |
| Angular twin drifts from React over time | Every spec is written as the mirror of a named React test, and the mapping is in the table above so the next person can find the pair. |
| Three more Angular components adds package weight | All eight reuse existing CSS; the only new shared code is the ~20-line reduced-motion signal. |

</Section>
