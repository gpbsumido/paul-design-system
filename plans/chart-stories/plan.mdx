PR C of a 3-PR stack, on top of `ps/specialty-charts` (#44). The last of the
follow-ups disclosed on #42.

<Section id="why" title="What's missing">

`packages/storybook` covers 23 components. After PRs A and B the system has
eleven chart forms and eight more Angular twins, and the chart half of that has
almost no visual surface: `Sparkline`, `BarChart` and `DonutChart` have one
story file each, and nothing covers the eight new forms at all.

Two smaller problems this fixes on the way:

- `DonutChart.stories.tsx` hardcodes hex colours (`#22c55e`, `#f59e0b`, `#ef4444`) in its default args. That was always a bad example to set — it bypasses the token palette — and after the recolour in PR B it also renders the *old* colours next to components using the new ones.
- Nothing screenshots dark mode for the charts. PR B validated the dark palette numerically; nothing has looked at it.

Storybook here is React-only (`@storybook/react-vite`), so these stories cover
the React components. The Angular twins are pinned by their TestBed specs and by
the DOM-parity assertions in each spec, not by Chromatic.

</Section>

<Section id="risks" title="Risks">

| Risk | Mitigation |
|---|---|
| Chromatic will flag every existing chart snapshot as changed | Expected — that's the PR B recolour showing up. Called out in the PR body so it isn't mistaken for a regression. |
| The gallery story is a single snapshot that changes whenever any chart changes | That's the point; the per-chart stories localise the diff. |
| Storybook 8 with React 19 in this repo | Already the case for 23 components; nothing new here. |

<Section id="deferred" title="Explicitly deferred">

- **Angular stories.** Storybook here is React-only; adding `@storybook/angular` means a second builder and a second build in CI. Its own change.
- **Interaction tests** (`play` functions) for the charts — they're static SVG, so there's nothing to drive until the hover layer lands.
- **The hover/tooltip layer and table-view fallbacks**, still deferred from PR B.
