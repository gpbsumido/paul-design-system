<Section id="why" title="Why & approach">

paul-explore draws its charts with `recharts` (React-only) and `@unovis` — see
`src/app/work-portfolio/demos/chart-library.tsx` (17-type gallery),
`src/components/operator/{FleetHealthChart,AlertTrendChart,InventoryComparisonChart}.tsx`,
and `src/app/vitals/VitalsChart.tsx`. Neither library runs in Angular, so
lifting them verbatim can never satisfy "reusable everywhere".

Instead I compute chart geometry (line/area paths, bar rects, donut arcs) in a
**pure, dependency-free TS core** and render plain SVG. React and Angular render
identical SVG from the same math; the published packages gain **no** charting
runtime dependency; the theme comes from existing tokens. This is the only
approach that gives true React/Angular parity for a framework-agnostic system.

</Section>

<Section id="architecture" title="Architecture">
  <Mermaid>{`flowchart LR
    G["chartGeometry.ts (pure)\\nlinePath / areaPath / barRects / donutSegments"] --> R["React: Sparkline / BarChart / DonutChart"]
    G --> A["Angular: PaulSparkline / PaulBarChart / PaulDonutChart"]
    C["css: chart.css (token palette)"] --> R
    C --> A`}</Mermaid>

The geometry core is small pure math, duplicated identically in the `react` and
`angular` packages (no shared JS-logic package exists, and adding one would drag
in build-order/publish complexity for ~80 lines). Both copies are unit-tested so
they cannot drift silently.

</Section>

<Section id="geometry" title="Geometry core — the reusable delta">

| Function | Returns | Backs |
|---|---|---|
| `linePath(values, box)` | SVG `M..L..` path | Sparkline line, Vitals trend |
| `areaPath(values, box)` | closed path to baseline | Sparkline area, AlertTrend |
| `barRects(values, box, opts)` | `{x,y,width,height,value}[]` | BarChart vertical |
| `barRectsHorizontal(values, box, opts)` | same, rotated | InventoryComparison |
| `donutSegments(values, opts)` | `{path,percent,startAngle,endAngle,index}[]` | FleetHealth, Revenue mix |
| `polarToCartesian` / `arcPath` | arc helpers | donut internals |

Edge cases pinned by tests: empty data, single point, all-zero series, one non-zero slice.

</Section>

<Section id="components" title="Components">

| Component | Package | Reuses | API |
|---|---|---|---|
| `Sparkline` | react `src/Sparkline.tsx` | `cx`, geometry | `data:number[]`, `variant:'line'\|'area'`, `label`, `width`, `height` |
| `BarChart` | react `src/BarChart.tsx` | `cx`, geometry | `data:number[]`, `labels?`, `orientation`, `colors?`, `label` |
| `DonutChart` | react `src/DonutChart.tsx` | `cx`, geometry | `data:{label,value,color?}[]`, `label`, `legend?` |
| `PaulSparklineComponent` | angular `src/sparkline.ts` | geometry | signal inputs mirroring React |
| `PaulBarChartComponent` | angular `src/bar-chart.ts` | geometry | signal inputs mirroring React |
| `PaulDonutChartComponent` | angular `src/donut-chart.ts` | geometry | signal inputs mirroring React |
| `chart.css` | css `src/components/chart.css` | tokens | `.paul-chart*`, `--paul-chart-1..6` palette |

All charts render `role="img"` with an aria-label summary of the data (matching
paul-explore's a11y pattern), color never the only signal (legend text + values).

Parity batch (existing React → new Angular, CSS already shipped): `PaulDividerComponent`,
`PaulSpinnerComponent`, `PaulIconButtonComponent`, `PaulSwitchComponent`.

</Section>
