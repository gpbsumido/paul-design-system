<Section id="key-changes" title="Key changes">

**One axis, enforced.** `paretoLayout` returns bars already expressed as
percent-of-total, so there is nothing to align against a second scale:

```ts
const total = sorted.reduce((sum, v) => sum + v, 0);
const percents = sorted.map((v) => round((v / total) * 100));
// …bars scale by (value / total) * 100 against the same box height the
// cumulative line uses, so the 80% crossing is a real position, not a coincidence.
```

and the component test refuses to let a raw count back in:

```
draws exactly one y-scale — no second axis and no raw-count labels
```

**Determinism, because SSR and Chromatic both depend on it.** No RNG anywhere in
the word cloud; the spiral is a pure function of the index:

```ts
const angle = step * 0.35;
const radius = 2 + angle * 2.2;
x = cx + Math.cos(angle) * radius;
y = cy + Math.sin(angle) * radius * 0.62; // wider than tall, like the box
```

**Ordered data gets the ordered ramp.** Funnel stages and heatmap cells map onto
`--paul-chart-seq-*`, never the categorical slots — and the tests assert both
directions, so a future edit can't quietly swap them:

```ts
expect(fill).toMatch(/--paul-chart-seq-\d/);
expect(fill).not.toMatch(/--paul-chart-\d(?!.*seq)/);
```

**Clamp, don't cycle.**

```ts
// A 7th series repeats slot 6 rather than wrapping to slot 1 — a repeat of the
// first slot would read as the first series. Past six, fold the tail into "Other".
`var(--paul-chart-${Math.min(i, 5) + 1})`
```
